## 1. 已锁定的事实（调研实测，非推测）

| 结论 | 证据 |
|---|---|
| **不存在**「中国门牌级 + 全球 + 免费」的单一服务商 | 三条硬因：测绘资质 / GCJ-02 强制偏移 / 国内图商协议禁止落库 |

| **Photon 会返回错号** | 87 号 → `建国路75号数字艺术园区`（同路错号） |
| 百度/高德有门牌级能力 | 百度返回「北京市朝阳区八里庄街道建国路87号（北京SKP）」 |

## 4. 坐标处理

- **规范化存储 WGS-84**（数据库唯一真相）
- 中国源返回 GCJ-02 → 用 `gcoord@1.0.8`（MIT）转 WGS-84 后入库
- 反向（若未来用 GCJ-02 底图）再转回
- **不要**引入 `eviltransform`（已废弃）
- 每条地点额外记录 `coordSystem`（原始坐标系）与 `provider`，便于将来排查偏移

## 5. 数据模型影响（最小改动）

现有 `Stop` / `Trip` 已有 `lat/lng/address/bbox/timeZone/country/countryCode/provider/providerPlaceId`。

**新增（additive）**
- `Stop.addressComponents Json?`、`Trip.originAddressComponents Json?` —— 存省/市/区/街道/门牌/邮编的结构化分量（用户要求"详细地址"）
- `Stop.coordSystem String?`、`Trip.originCoordSystem String?` —— `wgs84` | `gcj02` | `bd09`（记录来源坐标系，便于将来排查）

**不新增**：不建 `Place` 表（我们存的是"用户选择过的地点快照"，不是地理库）。

## 6. 搜索 API（对外不变，内部路由）

`GET /v1/places/search?q=&limit=&country?`
- 内部按查询语种/国家推断路由（中文优先中国源，其余走全球源）
- 响应统一为：`{ provider, items: [{ name, address, addressComponents, lat, lng, timeZone, bbox, providerPlaceId, type }] }`，坐标**一律 WGS-84**
- 缓存：查询结果 Redis 300s（不落库）；**选中地点**才写入业务表
- 降级链：L1 主源 → L2 备源 → L3 返回 `degraded: true` + `fallback: "map_pick"`，前端展示「在地图上选位置」

## 7. 地图点选（新能力）

- 地点选择器底部提供「**在地图上选**」入口
- 进入地图后，用户点击 → 取该点 WGS-84 坐标 → **逆向填充**：我们自己的瓦片只能给坐标，不能给门牌地址
- 因此该路径的结果是：`name = "地图选点"`、`address = null`、`provider = "map_pin"`、坐标有效
- **明确标注**：这是兜底，不是地址搜索成功

## 9. 验收标准

- 中国一个具体门牌地址（如「建国路87号」）能返回门牌级结果，且坐标在地图上位置正确（**偏移 ≤ 20m**）
- 全球一个具体地址能返回结果
- 无 key 时不崩、不明示假数据，返回 `degraded` 并引导地图点选
- **Photon 在中国不再被调用**（日志断言）
- 选中地点后 `lat/lng` **自动填充**，用户全程不手输经纬度
