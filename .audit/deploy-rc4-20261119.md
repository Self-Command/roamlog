## 上线过程中真实遇到并修掉的两个阻断

1. **`minio-init` 无法启动**：`.env.staging` 的 `MINIO_MC_IMAGE` 指向 `chainguard/minio-client`（distroless，无 `/bin/sh`），而启动命令是 shell 脚本。staging 里这个容器其实一直是 `exited(2)`，只是没人注意。
   → 生产 compose 里改为 **opt-in profile**（`--profile init`），且 `api`/`worker` 不再依赖它；否则一个引导容器失败会把整个应用层拖住。
2. **媒体端口不生效**：`minio` 只挂在 `internal: true` 的 `backend` 网络，**Docker 对 internal-only 网络不建立发布端口**，所以宿主 nginx 到 `127.0.0.1:19000` 不通（但 API 通过服务名访问是通的，`/v1/ready` 的 storage 检查因此仍显示 up，具有欺骗性）。
   → `minio` 同时加入 `edge` 网络，端口仍绑 `127.0.0.1`。
3. **CORS**：MinIO **不实现 S3 bucket CORS API**，所以 `mc cors set` 思路无效；改用服务端 `MINIO_API_CORS_ALLOW_ORIGIN`（由 `MEDIA_CORS_ORIGINS` 注入）。

以上 3 条已固化为 `c27b99f` + `061ef23` 并同步到服务器；**不带任何 override** 重建验证通过。

## 已知问题（部署后必须处理）

1. **邮件发不出去（P0）**：Gmail SMTP 在 `AUTH PLAIN` 阶段被 Google 直接断连（EHLO 正常）。服务器 465/587 均可达，判断为 **Google 屏蔽该 VPS 出口 IP** 或 **app password 失效/未开两步验证**。
   - 影响：注册验证、邀请、密码重置、导出通知、提醒全部不会送达。
   - API/worker 均不会因此崩溃（发送时才失败，且已分级为可重试/不可重试）。
   - 建议：改用 Resend（配已验证域名）或换一家 SMTP relay；若坚持 Gmail，需确认 app password 与账号两步验证状态，并用 `swaks`/`openssl` 复测。
2. **无自动备份**：本次为手工 `pg_dump`。`deploy/backup-roamlog.sh` 只支持旧 staging 双文件编排，且 crontab 为空。需要新的生产备份脚本 + 定时任务。
3. **`minio-init` 未执行**：bucket `roamlog` 是既有数据，`/v1/ready` storage 检查通过；但**新环境首次部署必须先跑一次 init**（见 release-checklist §12）。
4. **媒体对象未做真实上传验证**：本地无 Docker 无法联调；线上 CORS 与验签路径已验证，但"真实 PUT 一张图 → complete → ready → 显示"仍需一次真机操作。
5. GHCR 拉取曾出现一次瞬时失败，重试即成功；发布时需允许重试。
